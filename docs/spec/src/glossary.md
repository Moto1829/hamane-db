## ベクトル検索の基礎

### 埋め込み (embedding) / ベクトル

文章や画像を、意味の近さが距離に対応するように数値の並びへ変換したもの。
「犬」と「子犬」は近く、「犬」と「経理」は遠くなります。
変換は埋め込みモデル (OpenAI や各種 OSS モデル) が行い、hamane-db は
**出来上がった数値の並びを保存して検索する**役割です。

→ [データモデル](data-model.md)

### 次元 (dim)

1 本のベクトルに並ぶ数値の個数。モデルごとに決まっていて (例: 384、768、1536)、
collection を作るときに指定します。**後から変えられません**。

### メトリック (metric) — L2 / コサイン / 内積

「近さ」の測り方。

| 種類 | 意味 | 使いどころ |
|---|---|---|
| `L2` | 直線距離。**小さいほど近い** | 座標のような値をそのまま比べたいとき |
| `Cosine` | 向きの一致度。**大きいほど近い** | 文章の埋め込み。長さの違いを無視したいとき |
| `Dot` | 内積。**大きいほど近い** | 推薦など、大きさ (人気度) も効かせたいとき |

Cosine では投入時にベクトルの長さを 1 に揃えます (正規化)。

→ [データモデル](data-model.md#metric-距離関数)

### 近傍検索 / k-NN

クエリのベクトルに近いものを上位 `k` 件返すこと。「k 近傍」とも。

### 近似最近傍 (ANN) と「正確な検索」

全件と距離を比べれば必ず正解が出ますが、件数に比例して遅くなります
(これを **Flat 検索** / 総当たりと呼びます)。
そこで**多少の取りこぼしを許して桁違いに速くする**のが近似最近傍探索です。
hamane-db はセグメントに対して近似 (HNSW / IVF)、memtable に対しては
Flat を使い、結果をまとめます。

### recall@k (再現率)

近似検索の正確さの指標。「正解の上位 k 件のうち、実際に返せた割合」。
recall@10 = 0.98 なら、10 件中 9.8 件は総当たりと同じものが返っている、
という意味です。

→ [ベンチマーク](benchmarks.md)

### QPS

1 秒あたりに処理できる検索の数 (queries per second)。

## 索引 (探索を速くする仕組み)

### 索引 (index)

全件を見なくても近いものに辿り着けるようにした補助データ。
hamane-db では **HNSW** か **IVF** のどちらかをセグメントごとに作ります
(両方は作りません)。

### HNSW

ベクトル同士を「近いもの同士」で結んだグラフを階層に積み、
上の階層でおおまかに近づいて下の階層で精密に探す方式。既定の索引です。

→ [検索](search.md)

### ef / ef_search / ef_construction

HNSW の**探索の幅**。大きいほど候補を多く見るので**精度が上がって遅くなり**ます。
`ef_search` は検索時 (クエリごとに変更可)、`ef_construction` は
グラフを作るときの値です。

→ [設定リファレンス](configuration.md#hnswparams)

### m / m0

HNSW の 1 ノードが持つ**つながりの数**の上限。大きいほど精度が上がり、
メモリと構築時間が増えます (`m0` は最下層ぶん)。

### IVF (転置ファイル)

ベクトルをあらかじめクラスタに分けておき、**クエリに近いクラスタだけを見る**方式。
HNSW と違ってグラフを持たないぶんディスクが小さくなります。

### nlist / nprobe

`nlist` は IVF が作るクラスタの数、`nprobe` は検索時に見るクラスタの数。
`nprobe` を増やすほど**精度が上がって遅くなり**ます (検索ごとに変更可)。

→ [検索](search.md#ivf-による枝刈り)

## 量子化 (メモリを減らす仕組み)

### 量子化 (quantization)

ベクトルを**粗く表現して小さくする**こと。32 ビットの小数の並びを、
1 バイトの整数やコード番号に置き換えます。メモリと帯域が減るぶん、
距離の計算は近似になります。

→ [検索](search.md#量子化による高速化)

### 2 段階検索 と 再ランク (rerank)

量子化した粗い距離で**候補を多めに絞り** (1 段目)、
最後に元の f32 のベクトルで**正確に並べ直す** (2 段目 = 再ランク) 方式。
これにより、**返ってくるスコアは常に正確な距離**になります。

### SQ8 (スカラー量子化)

各次元の値を 1 バイト (0〜255) に丸める方式。元の 1/4 のサイズ。
実装が単純で速く、精度の劣化も小さいので**まず試す候補**です。

### PQ (直積量子化)

ベクトルを `m` 本の短い区間に切り、区間ごとに「代表ベクトル 256 個」の
どれに近いかの**番号だけ**を保存する方式。1 本を数十バイトまで圧縮できます。

### サブベクトル / コードブック / コード

PQ で切り分けた各区間が**サブベクトル**、区間ごとの代表ベクトル集合が
**コードブック**、「どの代表に近いか」の番号列が**コード**です。

### ADC (非対称距離計算)

PQ の距離の求め方。クエリは量子化せずに、
「クエリと各代表ベクトルの距離」を先に表 (LUT) にしておき、
各レコードは**表を引いて足すだけ**で距離を推定します。

### nbits

1 つのサブコードに使うビット数。8 なら代表 256 個で 1 バイト、
4 なら代表 16 個で半バイト。**4 にするなら `m` を 2 倍**にするのが定石です。

→ [設定リファレンス](configuration.md#索引と量子化の組み合わせ)

### OPQ (回転付き PQ)

PQ の前にベクトル全体を**回転**させてから区間に切る方式。
区間ごとの情報量の偏りをならせるので、次元の並びに意味がないデータ
(多くの埋め込み) で精度が上がります。回転しても距離は変わりません。

### IVF-PQ / 残差

IVF でクラスタに分けたうえで、「クラスタ中心からのずれ」(= **残差**) を
PQ で圧縮する方式。ずれだけを表すので、そのまま PQ にかけるより誤差が小さくなります。

## 保存の仕組み

### WAL (先行書き込みログ)

書き込みをまず追記するログファイル。**ここに書いて fsync した時点で
「保存された」と返す**ので、直後にプロセスが落ちても復旧できます。

→ [永続化と耐久性](persistence.md)

### fsync

OS のバッファではなく**ディスクに本当に書き込ませる**システムコール。
遅いですが、これをしないと電源断でデータが消えます。

### group commit

同時に走っている複数の書き込みの fsync を**1 回に相乗り**させる仕組み。
耐久性は変わらないまま、並行書き込みのスループットが上がります。

### memtable

まだファイルにまとまっていない、**メモリ上の書き込みバッファ**。
検索時はここも見ます。一定量たまるとセグメントとして書き出されます。

### セグメント (segment)

memtable を書き出してできる**不変のファイル群**
(ベクトル・ID・メタデータ・索引など)。一度書いたら変更しません。
新しいデータは常に新しいセグメントになります。

→ [オンディスクフォーマット](file-format.md)

### フラッシュ (flush)

memtable をセグメントとして書き出す操作。索引の構築もこのときに行います。
閾値を超えると自動で走ります。

### コンパクション (compaction)

増えたセグメントを**統合して整理する**操作。上書きされた古い版や
削除済みのデータをここで物理的に消すので、ディスク使用量が収束します。

### tombstone (墓標)

「このレコードは削除された」という印。セグメントは不変なので、
削除は**消す代わりに印を置く**ことで表現し、コンパクションで実際に消します。

### newest-wins

同じ ID が複数の場所 (memtable と複数のセグメント) にある場合、
**一番新しいものだけを有効**とする解決ルール。

### manifest

「今どのセグメントが有効か」を記録したファイル。
更新は新しい世代を書いてから `CURRENT` を差し替えるので、
途中で落ちても**中途半端な状態が見えません**。

### mmap

ファイルをメモリ上のデータのように直接読む仕組み。
読み込みのためのコピーが要らないので、セグメントの読み取りに使っています。

### CRC32C

データが壊れていないかを確かめるためのチェックサム。
各ファイルの末尾に付けてあります。

### バックプレッシャー

書き込みが速すぎてフラッシュが追いつかないとき、
**メモリを守るために書き込み側を待たせる**こと。

## 運用

### レプリカ / 昇格

`--replicate-from` を付けて起動した**読み取り専用の複製**がレプリカです。
primary から定期的に取り込んで追従します。primary が落ちたら、
このオプションを外して再起動するだけで書き込み可能になります (= **昇格**)。

→ [レプリケーション](replication.md)

### スナップショット

ある時点の状態の写し。検索は開始時のスナップショットを見るので、
途中でフラッシュやコンパクションが走っても結果が壊れません。

### バックアップ

`backup` は**一貫性のあるコピー**を作ります。復元は「そのディレクトリを
開くだけ」です。

→ [永続化と耐久性](persistence.md#バックアップ)
