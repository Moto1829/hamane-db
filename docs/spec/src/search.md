# 検索

## API

```rust
let hits: Vec<SearchHit> = col.search(&query)
    .k(10)                            // 取得件数 (既定 10)
    .filter(Filter::eq("lang", "ja")) // メタデータフィルタ (任意)
    .ef(128)                          // HNSW 探索幅の上書き (任意、既定 64)
    .run()?;

pub struct SearchHit {
    pub id: Id,            // u64
    pub score: f32,        // 意味はメトリック依存 (下表)
    pub metadata: Metadata,
}
```

結果は**近い順**に並びます。

| Metric | score | 並び順 |
|---|---|---|
| `L2` | ユークリッド距離 | 昇順 |
| `Cosine` | コサイン類似度 | 降順 |
| `Dot` | 内積 | 降順 |

## 実行モデル

検索はスナップショット上で実行されます。開始時点の memtable と
セグメント集合が対象になり、検索中の書き込み・フラッシュ・コンパクションの
影響を受けません (ブロックもしません)。

データソースごとの実行方式:

| ソース | 方式 | 正確性 |
|---|---|---|
| memtable (未フラッシュ分) | Flat (全走査) | 正確 |
| セグメント (HNSW なし = 小規模) | Flat | 正確 |
| セグメント (HNSW あり) | HNSW | **近似** |

各ソースの上位 k を距離順にマージして最終結果を返します。

## 一貫性の保証

- **削除済み・上書き済みレコードは決して結果に現れない**。
  複数セグメントにまたがる同一 id は、最も新しい書き込みだけが有効
  (newest-wins)。この判定は走査時に行われるため、Flat 経路では
  古い値が新しい値を押し出すこともない
- 挿入・削除は**即座に**検索へ反映される (インデックス構築を待たない)
- 同距離のタイは id 昇順で決定的に順序づけられる (Flat 経路)

## 近似性 (HNSW) について

HNSW を持つセグメントに対する検索は近似です。再現率は `ef` で制御します:

- `ef` は「探索中に保持する候補数」。大きいほど再現率が上がり遅くなる。
  実効値は `max(ef, k)`
- 既定パラメータ (`m=16, ef_construction=200, ef=64`) での実測は
  SIFT1M で recall@10 = 0.977 ([ベンチマーク](benchmarks.md))
- `ef` をレコード数以上にすると実質的に全探索と一致する

HNSW が構築されるのはフラッシュされたセグメントのうち行数が
`hnsw_min_rows` (既定 1024) 以上のものだけです。それ未満のセグメントと
memtable は常に正確検索されます。

## フィルタ付き検索の実行戦略

フィルタがある場合、セグメントごとに選択率 (フィルタ一致率) を
サンプリング推定し、実行戦略を自動選択します:

| 選択率 | 戦略 | 内容 |
|---|---|---|
| < 5% | **pre-filter** | メタデータを走査して一致行だけ距離計算 (正確) |
| ≥ 5% | **post-filter** | HNSW 探索中に不一致候補を棄却。探索幅を最大 4 倍に自動拡大 |

注意: post-filter は近似のため、一致レコードが存在しても k 件に
満たない結果が返る可能性があります。厳密性が必要な場合は `ef` を
大きくしてください。

## 量子化による高速化

`StoreOptions.quantization` で有効化します (既定 `None`)。フラッシュ時に
量子化したベクトルを別ファイルにも書き、HNSW 探索 1 段目の距離計算を
軽い演算に置き換えます。**元の `vectors.bin` は必ず残る**ので、量子化の
有無にかかわらず最終結果は f32 の正確な距離で再ランクされます。

| 方式 | 指定 | 1 行あたり | 1 段目の距離 |
|---|---|---|---|
| SQ8 | `Some(Quantization::Sq8)` | dim バイト (f32 比 1/4) | u8 の整数演算 |
| PQ | `Some(Quantization::Pq { m })` | `ceil(m × pq_nbits / 8)` バイト (dim=128, m=32, 8bit で 1/16) | LUT の表引き加算 (ADC) |

- 探索は量子化距離で上位 k×4 件 (4-bit PQ は k×8 件) を取り、f32 の正確な距離で
  再ランクして上位 k を返す (2 段階検索)。**返される score は常に正確な f32 距離**
- SQ8 の量子化は全次元共通の min/max (グローバルスケール)
- PQ は dim を m 本のサブベクトルに分け、サブベクトルごとに 256 個の
  セントロイド (コードブック) を学習します。コードブックはセグメント構築時に
  固定され、以後変わりません
- フィルタなしの HNSW 経路にのみ適用される。pre-filter (Flat) 経路は
  常に f32

### 4-bit サブコード

`StoreOptions.pq_nbits: 4` でサブコードを 4 ビット (16 セントロイド) にし、
2 サブコードを 1 バイトに詰めます。1 行のコードは半分になりますが 1 段目の
順位付けは粗くなるため、再ランク候補を `k×8` に広げています。

**メモリを固定して比べるなら `m` を 2 倍**にするのが基本です。SIFT 実測では
`m=64, 4bit` が `m=32, 8bit` と同じ 32 B/行で recall・QPS ともに同等以上、
構築は 2.3 倍速いという結果でした (詳細は [ベンチマーク](benchmarks.md))。
距離推定はバイト値をそのまま引く合成テーブルで行うため、表引き回数は 8bit と
同じです。

### OPQ (回転付き PQ)

`StoreOptions { quantization: Some(Quantization::Pq { m: None }), opq: true, .. }`
で有効化します。PQ の符号化前に直交行列 `R` を学習し、`R x` に回転してから
量子化します。直交変換は距離を保存するので**検索の意味は変わらず**、
サブベクトル間の分散の偏りが解消されて量子化誤差だけが下がります。

- 回転行列はセグメントごとに `opq.bin` (dim × dim の f32) に保存されます
- 検索時はクエリを同じ行列で回すだけで、再ランクは生の f32 のまま
- コードブック学習の前に交互最適化を回すため**構築は遅くなります**
  (実測は [ベンチマーク](benchmarks.md))

## IVF による枝刈り

`StoreOptions.index` を `Ivf` / `IvfPq` にすると、HNSW グラフの代わりに
転置ファイル (粗クラスタ) を構築します。HNSW と IVF はセグメント単位で
排他です。

- 構築時に粗 k-means で `nlist ≈ √count` 個のクラスタを作り、各行を
  最近クラスタに割り当てます
- 検索はクエリに近い `nprobe` 個のクラスタだけを走査します
  (`StoreOptions.nprobe`、クエリごとに `.nprobe(n)` で上書き可)
- `IvfPq` は各行を「所属セントロイドとの残差」として PQ 符号化します
  (IVFADC)。生 PQ より量子化誤差が小さくなります

## 実行の並列性

複数セグメントを持つ collection では、セグメントごとの探索が
Database 全体で共有する常駐スレッドプールで並列実行されます
(セグメント 1 個以下では逐次)。並列度は
[`StoreOptions.search_threads`](configuration.md#storeoptions)
で指定します (0 = 自動 = 論理コア数、1 = 逐次)。

## 計算量の目安

| 操作 | 計算量 |
|---|---|
| Flat 検索 (memtable / 小セグメント) | O(n log k) |
| HNSW 検索 | O(ef · log n) 相当 (経験的) |
| 点参照 `get(id)` | O(セグメント数 × log n) |
| `len()` | O(1) (書き込み時に差分維持) |
