## ゴール

「これより近いものだけ」を返せるようにする。重複排除・マッチング・
「該当なしなら 0 件」を表現したい用途で必要になる。

現状は `k` 件を必ず返すので、遠いものしか無くても k 件返ってしまい、
呼び出し側が score を見て自前で切る必要がある。

## やること

- [x] `SearchBuilder::threshold(f32)` (バッチ側にも同じものを)
- [x] 意味は **metric に応じて自然な向き**に揃える:
      L2 は「距離が threshold 以下」、Cosine / Dot は「スコアが threshold 以上」。
      内部の比較キーに直すと **どちらも `key <= key_from_score(threshold)`**
      になるので、実装は 1 箇所の比較で済む
- [x] k との関係を明記: 閾値で絞った上で上位 k 件。
      閾値を満たすものが k 件未満なら**それだけ返る** (0 件もあり得る)
- [x] HTTP / CLI / Python にも露出する
- [x] 量子化構成でも意味が変わらないこと (score は常に正確な f32 距離なので、
      閾値判定は再ランク後の値で行う)

## 完了条件

- [x] L2 / Cosine / Dot の 3 メトリックで境界が期待どおり
- [x] 閾値なしの結果から「閾値を満たすもの」を抜いた集合と一致する
- [x] 該当 0 件でエラーにならず空が返る

## 実装メモ

- 内部キーに直すと **どちらの向きも `key <= key_from_score(threshold)`** に
  なるので、比較は 1 箇所で済む (設計どおり)
- **ただし L2 は例外がある**。L2 の内部キーは距離の**二乗**なので、
  負の閾値を二乗すると符号が消えて「距離 ≤ |t|」になってしまう。
  距離は 0 以上なので負の閾値では必ず 0 件、が正しい。
  テスト (`threshold_filters_by_score`) がこれを捕まえた
- 判定は `finalize` (再ランク後) で行うので、量子化構成でも意味が変わらない
- HTTP / CLI / Python の全経路に露出した
