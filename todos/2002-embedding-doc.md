## ゴール

**最初に必ず出る疑問に、仕様書が答えていない。**

「hamane-db はベクトル化をどうやっているのか」は、ベクトル DB を初めて
触る人が最初に持つ疑問。実際の答えは「**していない。埋め込みは外部の
モデルの仕事で、hamane-db は出来上がったベクトルを保存・検索する**」だが、
これが仕様書のどこにも書かれていない。

用語集 (2001) の「埋め込み」項目に 1 行あるだけで、
「では自分は何を用意すればいいのか」に辿り着けない。

## 実装メモ

- `getting-started.md` に「ベクトルはどこから来るのか」節を **最小の例の前**に
  置いた。コードを書き始める前に読む位置でないと意味がないため
- 図で役割分担を示し、「SQLite が文字列の意味を解釈しないのと同じ立場」と
  言い切った。DB 側がモデルを抱えない理由 (用途・言語・コストで選ぶもの) も併記
- Python は **sentence-transformers → numpy → `upsert_batch`** の実際に動く形で
  書いた。Rust は埋め込み手段が環境依存なので `embed_with_your_model(text)` の
  プレースホルダにして、渡し方だけ示した
- 「決めておくこと」に dim 固定・モデル差し替え時は `swap_collections`・
  metric は Cosine が定番・**別モデルの出力を混ぜない**を明記
- `rag_pipeline.rs` の疑似埋め込みが意味を捉えないことを仕様書側からも書いた
  (例を読んだ人が本物だと誤解しないように)

## 検証の限界

Python の例のうち **sentence-transformers を呼ぶ行は CI で実行していない**
(モデルのダウンロードが要るため)。hamane 側の API 呼び出し
(`create_collection` のキーワード引数、numpy 行列の `upsert_batch`、
numpy クエリの `search`) は既存の pytest で実行されている形と同じ。
