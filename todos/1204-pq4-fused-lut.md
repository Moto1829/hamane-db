# 1204: 4-bit PQ のバイト単位合成 LUT

- Status: DONE (2026-09-06)
- Milestone: M12
- Depends: 1202
- Design: docs/design/quantization.md §8.5

## ゴール

4-bit PQ の距離推定を、バイト値をそのまま引く合成テーブルにして表引き回数を
半分にする (1203 で計測した QPS 低下を取り戻す)。

## やること

- [x] `build_lut` が nbits=4 のとき `(m/2) × 256` の合成表を返す
      (`lut[i][b] = sub[2i][b & 0xf] + sub[2i+1][b >> 4]`)
- [x] `distance_key` はバイト値で直接引く (ニブル展開が消える)
- [x] m が奇数のときは末尾 1 サブベクトルを 16 エントリ表で持つ
- [x] 合成表と従来のサブベクトル別表で結果が一致することをテスト

## 完了条件

- [x] 4bit の recall が 1203 と同じ (数値が変わらない = 純粋な高速化)
- [x] 4bit m=64 の QPS が 8bit m=32 に近づく

## 実装メモ

- `build_lut` の戻り値の形が nbits で変わる (8bit: m×256 / 4bit: (m/2)×256)。
  呼び出し側 (`distance_key`) が同じコードブックの表しか受け取らないので、
  API は変えずに済んだ
- 実測 (SIFT 200k): m=64 で QPS 6391 → **9492** (8bit m=32 の 9402 と同等)、
  m=32 で 8835 → **12012**。recall は完全に不変 (純粋な高速化)
- これで「同じコード長なら 4bit × m 2 倍」が recall・QPS・構築時間の
  全てで 8bit 以上になった
