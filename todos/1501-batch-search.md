# 1501: バッチ検索 (複数クエリを 1 回で)

- Status: DONE (2026-09-11)
- Milestone: M15
- Depends: 801 (検索スレッドプール)
- Design: —

## ゴール

複数のクエリベクトルを 1 回の呼び出しで検索できるようにする。

現状の `search` は 1 クエリ 1 回で、呼ぶたびに
`Store::view()` (ロック取得 + LiveView 構築) からやり直す。
HTTP や Python から使うときは**往復とオーバーヘッドが支配的**で、
「100 件のクエリを投げる」が 100 回の往復になる。

また、セグメントが 1 個しかない DB では現状の並列化 (セグメント間) が効かない。
バッチならクエリ間で並列化できるので、単一セグメントでも並列度を活かせる。

## やること

- [x] `Collection::search_batch(queries) -> BatchSearchBuilder`。
      `k` / `filter` / `ef` / `nprobe` / `threshold` は既存 builder と同じ
- [x] `run()` は `Vec<Vec<SearchHit>>` (入力順)
- [x] `LiveView` はバッチで 1 回だけ取得して `Arc` で共有する
      (クエリごとのロック取得をなくす)
- [x] **クエリ間の並列化**: 既存の `SearchPool` に 1 クエリ 1 ジョブで積む。
      各クエリの中ではセグメントを逐次に見る (二重の並列化で
      オーバーサブスクライブしない)
- [x] クエリ 1 本 / プール並列度 1 のときは逐次実行にフォールバック
- [x] HTTP: `POST /collections/{name}/search/batch`
- [x] Python: numpy の (n, dim) 行列をそのまま渡せる `search_batch`

## 完了条件

- [x] バッチの結果が 1 件ずつ `search` した結果と**完全一致**する
- [x] 単一セグメントでもクエリ並列が効く (逐次比で短縮することを計測)
- [x] 空のクエリ列、次元不一致、フィルタ併用が正しく扱える

## 実装メモ

- `run_search` を **plan / execute / finalize** に分解した。`SegmentSearch` が
  `Arc<LiveView>` を持つようにして、バッチではビューをクエリ間で共有する
- 並列の粒度は**クエリ単位**。各クエリの中ではセグメントを逐次に見る
  (`run_sequential`)。二重に並列化するとスレッドを奪い合うだけなので、
  粒度の粗い側を採った
- 計画づくり (次元検証・正規化) は先に全件やる。1 本でも不正ならバッチ全体を
  エラーにする (部分成功を返さない)
- **実測 (SIFT 相当の合成データ、20 万件 × dim=64、単一セグメント、500 クエリ)**:
  1 件ずつ 44.0ms → バッチ 5.1ms で **8.7 倍**。セグメントが 1 個だと従来の
  セグメント間並列が全く効かないので、そこが一番効く
- HTTP は `POST /collections/{name}/search/batch`、Python は
  `search_batch` ((n, dim) の numpy 行列をゼロコピーで読む)
